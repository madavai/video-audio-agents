# video-audio-agents

Four Claude Code agents (transcriber, translator, voice, publisher), one setup skill and one Python MCP engine. Users are non-developers.

## Rules
- Simple code. No abstractions for single use. No frameworks beyond the MCP SDK. If a change could be 50 lines, it is not 200.
- Every tool returns small JSON; every long step reports progress; every job can be stopped (Esc) and leaves no partial files.
- Never overwrite a user's file: use paths.free_path(). One folder per link.
- Models and binaries are never committed; every download goes through models.py with progress and resume.
- Never print or log secrets, cookies or the browser profile. Never commit .venv, outputs, profiles.
- Plain-English errors for users; tracebacks go to the log file only.
- The agents never post to any platform and never fetch music or images from the internet.
- Any change to a feature updates the agent file that uses it, the USER-GUIDE and the CHANGELOG in the same PR.
- Tests: `uv run --project plugins/video-audio-agents/engine pytest` from the repo root before every PR; add `-m slow` for voice tests when models are present.
- `claude plugin validate . --strict` and `claude plugin validate plugins/video-audio-agents --strict` pass before every PR.
- Python packages are pinned (uv.lock).
- The version lives only in `plugins/video-audio-agents/.claude-plugin/plugin.json` (never also in marketplace.json). Claude Code updates people only when it changes, so every PR that changes anything in the plugin folder raises it: a phase raises the middle number (0.5.0 → 0.6.0), a fix the last (0.5.0 → 0.5.1). Phase 7 makes it 1.0.0, the release. The top heading of CHANGELOG.md is the same number. If main moved past your number while you worked, take the next one.
- Windows first; keep paths and subprocess calls cross-platform (pathlib, no shell=True).
- Build in the order of docs/BUILD-PLAN.md; do not start a Wave 2 item during Wave 1.

## How the repo is laid out
- The repo root is the marketplace (`.claude-plugin/marketplace.json`, source `./plugins/video-audio-agents`) plus what only builders need: CLAUDE.md, docs, tests, CI.
- The plugin is `plugins/video-audio-agents/`: its manifest, `agents/`, `skills/` and `engine/`. Only this folder is copied to people's computers, so nothing in it may read files outside it, and nothing that is only for builders goes in it (the validator warns about a CLAUDE.md there).
- To use the plugin from this repo: `claude --plugin-dir plugins/video-audio-agents`.

## How the engine is put together
- The `engine` MCP server is declared in `plugins/video-audio-agents/.claude-plugin/plugin.json` (`mcpServers`). Never add a `.mcp.json` at the repo root: Claude Code opened in this folder would read it as a project server without substituting `${CLAUDE_PLUGIN_ROOT}`, and it fails.
- The engine's Python environment is `${CLAUDE_PLUGIN_DATA}/venv`: the server's `env` sets `UV_PROJECT_ENVIRONMENT`, and the setup skill's install steps run through `skills/setup/install.py`, which sets the same variable (a `$env:` assignment in PowerShell always asks the person, so the skill's commands stay plain `uv run`). `${CLAUDE_PLUGIN_ROOT}` is replaced on every update, so nothing that must last goes there; a uv command on the engine without the variable would build a second 3 GB environment inside the plugin.
- `engine/src/video_audio_engine/server.py` holds the tool definitions only; each calls a module.
- Slow tools run their work through `progress.run(ctx, work)`: it runs `work(job)` in a thread, sends progress at every 1%, and on Esc makes `job.report()` raise `Stopped` so the work can remove partial files.
- Raise `ToolError("one plain sentence")` for failures the person should read; anything else is logged to `<data>/engine.log` and reported as "Something went wrong".
- stdout carries the MCP messages: never `print` from code the server runs.
- The private data folder is `VAA_DATA` (Claude Code passes `${CLAUDE_PLUGIN_DATA}`); `paths.data_dir()` reads it.
- Models live in `<data>/models/<repo name>/`, pinned to an exact revision with exact file sizes in `models.MODELS`. ffmpeg lives in `<data>/bin/`.
- yt-dlp gets `logger=ToLog()` so nothing reaches stdout. Files a download made are tracked against the folder's contents before it started, so tidying never touches the person's other files.

## Tests
- The engine's tests are in `tests/` at the repo root (settings in `pytest.ini`), outside the plugin, so people don't receive them.
- Test media is generated by ffmpeg at test time from `tests/fixtures/jfk.wav` and served by a local web server (`conftest.py`).
- `.test-data/` at the repo root keeps ffmpeg and the fast speech model between runs (cached in CI). Tests that need them use the `with_models` fixture; every other test gets an empty data folder and a fake Documents folder.
- Test-only switches: `VAA_BROWSER_HEADLESS=1`, `VAA_BROWSER_WAIT=<seconds>`, `VAA_MODELS_URL=<local server>`.
